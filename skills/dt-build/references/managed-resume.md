# Managed coordinator resume

This is the entry contract for a watcher-launched coordinator, on either host. It resumes an existing authorized run; it does not repeat intake. The launcher supplies the run id, run folder, checkpoint path, host and coordinator id. Resolve script paths from this reference's skill folder, resolving a skill junction before walking to the repo root.

## Before marking bootstrap

1. When the bridge declares `mode="dt-build-lean"`, defer the canonical chain and root policy until the action needs them. The launcher sets `DT_BUILD_LEAN_BOOTSTRAP=1` only for headless Codex coordinators; it grants no authority. Otherwise complete the bridge's required reads fresh, fully and in order, without rereading native files; never reread a complete read, as the hook denies the third full read of a file and points to read-evidence slices. Read each file separately with enough output capacity; never batch full files into truncated or nested JSON output. Required authorization reads are never optional.
2. Read this reference and run `pwsh -NoProfile -File scripts/read-coordinator-rulebook.ps1 -CoordinatorHost <host>` from this skill's resolved directory. This emits exactly one host adapter plus current SKILL.md Model routing, Context discipline, milestone execution and Guardrails sections. It fails closed if a section is missing. Read the repo's `references/deterministic-reference-policy.md` and `references/conventions.md`. In ordinary mode read canonical `build-process.md` once; in lean mode defer it until a new build or close-out. Do not load the full skill, intake schemas, script source, template, session-audit skill, tech stack, brandbook or history during bootstrap. Gate contracts still load before their gates.
3. Read `_build-state.md` in full and the run's `build-state.md` and `build-plan.md`. Run `pwsh -NoProfile -File scripts/read-resume-record.ps1 -RunFolder <folder> -RunId <id> -BuildStatePath <checkpoint> -CoordinatorId <coordinator>`: it reads and verifies the registered run record, complete approvals, operator notes, lease and current status/cursor. A run pin is enforced by dt-job and wrappers: dispatch without `-Model` and never restate it in handoffs. Operator notes are standing instructions from Danny or his operator session: follow every one, ahead of anything in the checkpoint. A `context_wall` means earlier coordinators used up their working room without starting a job, including before bootstrap. Route inherited authority through the verified authority digest below; send other heavy evidence reads to a `mechanical` worker. A `kill_handoff` is the watcher's note for a coordinator stopped before it could hand off; read it, then confirm its jobs against the ledger. `worktrees` lists the trees this run's coordinators created (recorded and live); before adding a worktree, reuse the one on the right base rather than creating a parallel one. Verify branch and scope. Follow the authority read contract below: original records and explicit restrictions control authorization, even when a digest or summary says PASS. Missing or contradictory authority stops the dependent action. Never infer new authority from a previous coordinator's claim or a reference pack.
4. Use the supplied run folder, not a recursive workspace search. Never run `resume` or `approve`, never replace the registration or reacquire a watcher lease. A runnable registration and existing approvals do not authorize a new merge, push, deploy, production write, or irreversible operation.
5. Immediately run `dt-job mark-bootstrap -RunFolder <folder> -CoordinatorId <id> -Host <host> -Json` once, before reading job evidence, reconciling, dispatch preparation or implementation references. Marking is measurement, not permission. Target less than 50,000 input tokens; inspect the actual recorded baseline and retain it as evidence. Only the verified authority digest contract may defer inherited originals; current authority always stays before the marker.

## Carry on

- Reconcile, then read run-level status envelopes, checking `report_verdict` and `failure_category` alongside process status. Handle existing jobs before consuming their events. Read only the current milestone and next action; use the rulebook's execution sections, never repeat intake steps 1–5. Acceptance and verification contracts apply in full before their gates; a resume skips no checks.
- When contracts/glossary are needed, use the run-folder `reference-manifest.md` and its `reference-pack-contracts.md` / `reference-pack-glossary.md` instead of rereading their full source files as well. Check manifest hashes before trusting the packs. Packs are frozen contract data, not substitutes for current policy or approvals. Load the current milestone's applicable contract sections; give workers paths to larger implementation references.
- Read git policy before git actions, model-routing policy before dispatch, browser policy before browser work, tech-stack guidance before application-development work, and session-audit instructions at actual close-out. A worker implementing the application must perform its own governing reads; the coordinator must also read a triggered policy if it itself performs that action. Never preload all these policies just because they may be needed later.
- Dispatch through the host adapter and `dt-job`, with the resolver's selection and all run restrictions. Never read scripts just to discover their arguments when the adapter/step supplies the command. Long tests and audits are jobs. Collect results through capped envelopes; deeper evidence goes through `read-evidence.ps1`.
- On rotation, consume handled events before requesting continuation, preserve the checkpoint's two dt-job-owned lines, request `context_rotation`, release the lease, and end. Running jobs survive. A rotation with no new ledger job starts/completions/failures remains thrash, even if bootstrap was large.

## Lean checkpoint

On every rewrite, keep `_build-state.md` at most 8 KiB: current milestone, short completed ids/SHAs, active job ids, exact next action, run-folder evidence pointers, and all current approvals/restrictions or their authoritative source paths. Use `scripts/write-resume-checkpoint.ps1` for atomic replacement; it preserves dt-job's current status/cursor under the run lock and archives the prior checkpoint under `checkpoint-history/` in the run folder. Existing oversized checkpoints remain readable until their next rewrite.

Never copy operator notes into the checkpoint; they live in the run folder's `operator-notes.json`, and `dt-job status` and every wait show them. Put job history, custody/hash comparisons, failed attempts, detailed verification results and decision narrative in the run folder, never append them to the checkpoint. Do not discard operative boundaries to satisfy the size limit: retain them in a run-folder boundary record, name it in the checkpoint, and apply the authority read contract before marking bootstrap. Archive history before replacing it with a pointer. Use the canonical pipeline template's fields; no template read is needed until a rewrite.

## Authority read contract

The original records remain the authorization source. The digest is a mechanical navigation index, never an approval. Coordinators never author or edit its authority content, extracts, manifest or pin; invoke the scripts only.

1. Invoke `scripts/build-authority-digest.ps1 -RunFolder <folder> -BuildStatePath <checkpoint>` when no digest exists, then `scripts/verify-authority-digest.ps1 -RunFolder <folder> -BuildStatePath <checkpoint>`. Both run deterministically without a model. The checkpoint is the discovery root, always read in full: its authority text is pinned separately, excluding only the two dt-job-owned status/cursor lines so operator resume cannot invalidate the digest. Every authority original retains its full-file SHA256 and byte size. Verification hashes the JSON against `authority-digest.json.sha256`, hashes the Markdown against the manifest, rediscovers the source set, and recomputes every original hash and byte size. Any missing or uncovered source, mismatch or malformed manifest fails closed. Discovery supports literal paths, line/list-item aliases with spaced absolute values and recursive alias references, known aliases after glued prose, comma siblings and brace lists. A checkpoint's STOP boundary follows `inherited_boundary` to the counted `inherited_authority_sources` enumeration; each successor contributes its boundary, source disposition, scope and approval text. That structured list controls inherited coverage, rather than evidence references embedded in prose. Without an enumeration, literal references recurse conservatively. Missing named originals fail closed; unresolved non-authority checkpoint references remain visible in the manifest and Markdown diagnostics. No globs or workspace searches.
2. The bootstrap authority read budget is **32,000 characters** across the digest and mandatory originals (roughly 8,000 text tokens; actual tokenizer and marker measurements still govern the less-than-50,000 target). Below that authority-set size, read originals in full. Above it, or when `context_wall` exists, invoke `scripts/read-authority-digest.ps1 -RunFolder <folder> -BuildStatePath <checkpoint>` to read the verified Markdown in full, then every `mandatory_paths` original in full before marking. The checkpoint, run build-state/build-plan, complete approvals and operator notes remain mandatory. The explicit STOP boundary and checkpoint-required current stop restrictions remain mandatory. Named metadata clarifications expressly granting no new authority remain indexed supplemental originals for full reads before dependent actions. In legacy graphs, keep the last checkpoint boundary pointer and most recently written boundary mandatory. Never designate an older boundary as current to shrink bootstrap. If current authority plus digest exceeds the budget, stop; never omit current authority. JSON quotes up to 160 characters of operative lines. Markdown uses reversible directory/filename tables, and clips navigation excerpts with an explicit marker; structured lists retain excerpts in JSON and every path in Markdown. Legacy excerpt sizing reserves the full 8 KiB checkpoint ceiling. Neither format grants permission or replaces the governing full read. The separately verified registration/lease read still applies; mutable lifecycle records are not frozen into this authority manifest.
3. If verification fails, read originals in full before bootstrap as previously required. Missing or contradictory authority stops the dependent action. Use `scripts/read-authority-original.ps1 -RunFolder <folder> -BuildStatePath <checkpoint> -Path <absolute-original> -BootstrapFallback` for a full fallback read even if the context-wall/repeat-read guards rejected a direct read. Reach the hard wall? Install the prepared candidate with `write-resume-checkpoint.ps1`, request continuation, release, and stop; this handoff script remains allowed past the wall.
4. Immediately before each dependent merge, push, deploy, production write, approval-gated step or irreversible operation, identify **all** governing originals using the checkpoint, current authority and digest index. Invoke `scripts/read-authority-original.ps1 -RunFolder <folder> -BuildStatePath <checkpoint> -Path <absolute-original>` for each, then read every emitted original IN FULL. This script re-verifies the complete pinned set before emitting the source; changed hashes stop the action and require bootstrap fallback/rebuild. Read in separate calls with enough output capacity. No summary, excerpt, hash alone or prior coordinator claim authorizes the action. Recheck complete approvals and current restrictions at action time. Do not proceed on ambiguity, missing authority or contradiction. Below the hard wall these script reads bypass evidence/repeat-read limits; at the hard wall hand off first unless an already-open irreversible step permits continuation.

## Operator recovery after an authority wall and thrash stop

For read-only acceptance, add `-DryRun -OutputDirectory <external-folder>` to the builder and `-DigestDirectory <external-folder>` to the verifier. DryRun requires output outside both the run and checkpoint directories, and never publishes a live digest or pin. Inspect originals discovered, unresolved candidates, Markdown/bootstrap characters, deferred original bytes and mandatory full-read bytes in the verification result. A failed build writes discovery diagnostics at its output location and grants no authority.

After the release coordinator installs this fix, an operator can build and verify the digest before re-arming the stopped run. These commands write the digest only when the operator runs them; do not execute them during fixture-only development. Obtain the registered checkpoint from the dt-job registry for this run (no recursive search):

```powershell
cd "D:/Claude/_Claude-Workspace/Skill Creation/danny-skills"
$recoveryRunFolder = 'D:/Claude/_Claude-Workspace/OneDrive Migration/File Sorter/file-sorter/.dt-build/core-durability-20260922/core-durability-20260922'
. ./skills/dt-build/scripts/dt-job.ps1
$registration = Get-DtJobRegistryEntry -RunFolder $recoveryRunFolder
if ($null -eq $registration) { throw 'Run registration missing; keep run stopped' }
pwsh -NoProfile -File skills/dt-build/scripts/build-authority-digest.ps1 -RunFolder $recoveryRunFolder -BuildStatePath $registration.build_state_path
if ($LASTEXITCODE -ne 0) { throw 'Digest build failed; keep run stopped' }
pwsh -NoProfile -File skills/dt-build/scripts/verify-authority-digest.ps1 -RunFolder $recoveryRunFolder -BuildStatePath $registration.build_state_path
if ($LASTEXITCODE -ne 0) { throw 'Digest verification failed; keep run stopped' }
```

Then issue `/dt-build resume core-durability-20260922` in the operator session. This clears the thrash stop and re-arms the launch budget; the coordinator never issues resume itself. It reads current authority and the verified digest before marking and the governing originals before actions. Capacity refusals use separate 5/10/20 minute backoffs with a 35-minute total wait bound; exhaustion pauses with reason `capacity` and a distinct alert, without spending thrash, retry or launch-cap budgets. A later resume re-arms that budget too.
