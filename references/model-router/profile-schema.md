# Model router research profile (version 1)

One JSON object describes one model. Required fields are `schema_version` (integer `1`), `model` (model ID), `lane` (`codex` or `claude`), `researched_at` (ISO 8601 date or timestamp), `frontier` (Boolean), `voice_policy_check` (`passed`, `failed`, or `unknown`), and `categories` (object). The nine fixed category keys are those in `router-common.ps1`; `image-generation` applies only to the Codex lane. Each category contains `grade` (`strong`, `capable`, `weak`, `unknown`), `citations` (array), `benchmark_scores` (array), `price_per_token`, `tokens_per_task`, and `output_speed`. The last three are numeric evidence objects or null: `{ "value": nonnegative number, "source": citation }`. A benchmark score is `{ "name": string, "value": nonnegative number, "source": citation }`.

A citation has exactly `source` (name), `url` (absolute URL), `independent` (Boolean), `note` (short factual context), and `quote` (short verbatim excerpt). Vendor claims use `independent: false`. Numeric evidence uses the same citation form. No additional fields are used for routing. A model is eligible in a category only when graded `strong` or `capable` and supported by at least one independent citation. The profile date is retained to alert when evidence exceeds 90 days.

The profile's `frontier` field is retained for schema compatibility but ignored by the table builder. Frontier status comes from `frontier-models.json` and, for Codex, the live catalog description. URL-less citations cannot provide independent evidence. Duplicate JSON keys are parsed last-wins by PowerShell `ConvertFrom-Json`; the router does not use duplicate keys as a source of evidence. Numeric evidence and products must be finite and between zero and 1,000,000,000,000 inclusive.
