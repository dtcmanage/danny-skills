- JUNCTION TOPOLOGY vs repo-level references. Repo-level `references/`, `scripts/`, `assets/` are reached
  by skills via repo-relative `../../` paths anchored on the SKILL.md location. But every surface loads
  skills through PER-SKILL junctions (CLI `~\.agents\skills\<name>`, Codex `~\.codex\skills\<name>`, Cowork
  `plugin_<ULID>\skills\<name>`), and `..` traversal from inside a Windows junction resolves lexically into
  the junction tree, NOT the real repo root -- so `../../references` from a junction-loaded skill/script does
  not reach `danny-skills/references`. Phase 0's only consumer of this is the audit Appendix-A pointer (prose
  Claude reads, so it still resolves in practice via repo context). But every later phase wires SCRIPTS to
  repo-level primitives via this path convention. Phase 1 must resolve how repo-level shared content reaches
  skills across all three junction surfaces (e.g. junction references/scripts/assets too, junction the whole
  repo, or have scripts resolve the reparse-point target before walking up). Recommend settling this at
  Phase 1 start; consider a short design-loop touch if deemed architectural.
